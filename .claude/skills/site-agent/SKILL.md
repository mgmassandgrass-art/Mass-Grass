# Mass & Grass site agent

The owner talks to an AI agent in the admin panel (`/admin/`, tab "المساعد"). The agent is Claude called from the
Worker with tools; it is separate from Claude Code sessions and can only touch the site and its data.

## Pieces
- `worker/src/agent.js`: tool definitions (`TOOLS`), tool executors (`run`), the loop step (`agentStep`).
  One model call per HTTP request; the panel calls `/api/admin/agent` again while `done` is false (max 25 steps).
  Conversations live in D1 `agent_threads.messages` (Anthropic message format); every tool call is in `agent_log`.
- `worker/src/agent-knowledge.md`: the agent's system prompt (brand rules, site architecture, how to edit).
  **Update it whenever the site's structure changes** (new page, new product kind, new shared script).
- `worker/src/manifest.json`: editable files + built-in images, generated by `node worker/tools/manifest.mjs`
  (`npm run deploy` runs it first). It is baked into the prompt.
- Site files: original assets, overridden by D1 `site_files` (`published` for everyone, `draft` only for the admin
  with the `mg_prev=1` cookie from `/api/admin/preview?on=1`). Editable paths match `FILE_RE`
  (`*.html` at the root, `assets/*.js|css`). The admin panel and the Worker code are out of reach on purpose.
- Publishing is owner-only: the drafts bar in the panel (`POST /api/admin/drafts`). Every publish stores a version
  in `site_file_versions` (`file_history`, `restore_version`, `restore_original` tools).
- Data tools reuse the admin API in `shop.js` (`admin()`), so they validate exactly like the panel.
- Image library: D1 `images` (uploaded in chat or the "مكتبة الصور" tab, resized to WebP ≤1600px in the browser),
  served at `/assets/u-xxxxxxxx.webp`. Images are passed to the model by URL.

## Config
- Secret `ANTHROPIC_API_KEY` (`wrangler secret put ANTHROPIC_API_KEY`); var `AGENT_MODEL` in `wrangler.toml`.
- `ANTHROPIC_URL` overrides the endpoint for local tests (a scripted mock server; see git history of this skill's commit).

## Adding a tool
1. Add `{name, description, input_schema}` to `TOOLS` (keep `cache_control` on the last entry).
2. Add the `case` in `run()`; throw `Error` with a clear message on bad input (the model sees it and retries).
3. Add an Arabic label in `TOOLAR` in `prototype/admin/index.html`.
4. Mention it in `agent-knowledge.md` if the model needs guidance on when to use it.

## Safety rules to keep
- Owner-only (`isAdmin`: role admin + `info@massandgrass.com`). No publish tool for the agent.
- File edits go to drafts; data edits are live but limited to what the admin API allows.
- Never let the agent edit `admin/`, the Worker, secrets, or run arbitrary SQL.
